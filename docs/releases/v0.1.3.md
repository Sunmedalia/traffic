# traffic v0.1.3

## 升级变化

- 采集与分析分离：`traffic capture` / `traffic import` 保存原始证据；停采后运行 `traffic-console analyze --session DIR`，再使用 TUI / Web 查看。新会话采用布局 v3，分析结果按代原子切换；失败或取消保留上次完整结果，原始证据保持只读。
- `--rules`、正文上限、扫描和告警参数移至 `traffic-console analyze`；规则校验使用 `traffic-console rules check FILE`。旧版带 `index.sqlite` 的会话仍可查看和重新匹配规则。`--retention` 已删除。
- Web 新增规则管理、后台分析与停止任务、请求筛选、手动解码和命中统计；压缩解码输出有界，长文本解码不再触发参数栈溢出。
- 修复 IIS 动态附加后前批 HTTPS 请求遗漏：在后续 HTTP API 调用中恢复并验证请求上下文，按请求标识去重，记录恢复计数及附加窗口状态。
- eCapture 过载时有界丢弃并记录缺口；实时 PCAP 异步落盘使用有界队列，避免无限积压。队列满不保证零丢失。
- 新增 `--stop-timeout` 总停机等待预算；超时以失败状态返回。修复停机错误覆盖、重复关闭突破预算，以及状态快照共享映射的数据竞争。
- 优化 Web 轮询、查询和健康展示，拆分 TUI / Web 模块；doctor 默认提供中文报告，脚本可使用 `--json`。

## 下载与使用

共 10 个组件包：Ubuntu / CentOS 7+ 的 amd64、arm64，以及 Windows amd64；每个平台分别下载 `traffic` 采集器和 `traffic-console` 分析器。使用同版本 `SHA256SUMS` 校验，完整解压并保留随包依赖。

```sh
traffic doctor
traffic capture --ports 80,443 --duration 60s
# 将整个会话目录复制到分析机器后：
traffic-console analyze --session DIR
traffic-console web --session DIR
```

Linux 包内置静态 libpcap、配套 eCapture、Java Agent 和 glibc 2.17 基线的 OpenSSL 预加载库；Windows 包内置 WinDivert、便携 Python、Frida 和探针。Windows 采集需管理员权限及系统允许加载驱动；Linux 采集需相应权限。

## 验证与边界

- IIS 修复实机回归：20 轮 560 个 HTTPS 请求全部捕获，其中每轮前 10 个共 200/200；另有无预热 107 请求矩阵通过。此结果不代表所有 IIS 场景或高负载下零遗漏。
- Debian ARM64、Ubuntu x64、CentOS 7 x64 已有源码实机验证；后续 PR 7/8 的改动通过自动化回归，未重新完成远端高负载或八小时长压验收。
- HTTP/2 完整后端实机矩阵、部分后端排空与卸载确认仍待验收。停机预算限制程序等待，不能强制中断操作系统磁盘写入。CentOS 7 原生内核缺少 CO-RE BTF，HTTPS 通常需服务启动时加载预加载库；程序不会重启业务。
- 详见仓库 VALIDATION.md、docs/windows-iis-fix-2026-11-17.md 和 OPTIMIZATION.md。
