# traffic v0.1.1

本版本修正 v0.1.0 的发布打包方式，替代旧版发布。

- Linux / Windows 基础包只包含根目录下的采集器、分析器、必要许可证；Linux 另含可选 OpenSSL 预加载库。不含测试、压测、IIS 环境搭建脚本、构建补丁或历史验证文档。
- 首次运行任一二进制自动创建程序旁的 `sessions/` 与 `exports/`。默认采集路径与分析器目录一致，独立于启动时工作目录；显式 `--data-dir` / `--output` 可覆盖采集位置。源码构建位于 `bin/` 时使用上一级目录。
- 无参数执行 `traffic` 显示命令说明及数据路径，正常退出；`traffic-tui` 无参数打开会话选择界面。
- 新增 Windows 可选离线依赖 ZIP：Python 3.13.11 x64、Frida 17.5.1、运行探针与许可证。解压到程序目录，不需要系统 Python 或 pip。发布流水线原生验证便携 Python 的 Frida 导入、探针入口与程序目录初始化。
- Windows CGO 运行库静态链接，减少对系统 MinGW DLL 的依赖。

## 下载

| 文件 | 用途 |
| --- | --- |
| `traffic-v0.1.1-linux-amd64.tar.gz` | Linux x64 二进制 |
| `traffic-v0.1.1-linux-arm64.tar.gz` | Linux ARM64 二进制 |
| `traffic-v0.1.1-windows-amd64.zip` | Windows x64 二进制 |
| `traffic-v0.1.1-windows-amd64-deps.zip` | 可选 Windows 明文探针离线运行依赖，解压得到 deps/ |
| `traffic-v0.1.1-java.zip` | 可选 Java Agent |
| `SHA256SUMS` | 所有下载包的 SHA-256 校验值 |

解压后直接执行 `./traffic doctor`（Windows：`.\traffic.exe doctor`）；分析器使用 `./traffic-tui`。请解压到可写目录。数据目录按需生成，不打入安装包。

Windows 抓包需从 [Npcap 官方页面](https://npcap.com/#download) 安装驱动并启用 WinPcap API 兼容模式；驱动安装器由官方单独分发。依赖包用法见 [Windows 说明](https://github.com/Sunmedalia/traffic/blob/v0.1.1/docs/windows-dependencies.md)。探针仍需显式启用，程序不会自动安装驱动或附加业务进程。

Linux 包在 Ubuntu 24.04 构建，要求 glibc 2.39+ 与系统 libpcap；CentOS 7 等旧环境仍需从源码构建。eCapture 单独构建，Java Agent 适用 JDK 17/21 的受支持 Tomcat NIO 场景。GitHub 自动生成的 Source code 是开发源码，运行程序请下载上表的平台包。

本次主要调整发布与启动体验，不表示采集性能边界已全部解决：持续高负载接收预算、完整 Windows/容器/HTTP/2 实机矩阵与部分后端排空仍待验收。完整说明见仓库 [使用手册](https://github.com/Sunmedalia/traffic/blob/v0.1.1/docs/guide.md) 与验证记录。
