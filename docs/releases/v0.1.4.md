# traffic v0.1.4

本版集中修复 Windows 采集中断、Linux TLS 探针过载与停采，以及异常中断会话的证据恢复。采集器和本地分析器继续独立交付，推荐使用同版本配对。

## 采集与停机

- **Windows**：WinDivert 批量接收报文，使用 QPC 时间戳，停采时排空已接收队列。IIS 探针移除对动态返回地址的 hook，限制进程内正文复制和完成上下文恢复开销。省略的文件响应正文会标注截断和缺口。Windows OpenSSL 单次事件截断会记录遗漏字节数。
- **Linux eCapture**：采集器异常退出时，内核通知探针子进程退出。经过能力核验的探针使用 PID 白名单合并 root worker。发送队列拥塞后按有界策略丢弃事件并保留连接，回落后恢复发送。可恢复的断连按有上限的退避重新附加，发布序号缺口保留在证据中。
- **停采**：Linux eCapture 使用最终事件序号核对排空。OpenSSL Preload 停止接收新数据并尝试排空已入套接字的数据，缺少发送方最终确认时状态仍为 `unverified`。
- **慢盘**：默认 `--evidence-backpressure=strict`，证据写队列耗尽时停采。显式设置 `--evidence-backpressure=drop` 可在队列拥塞时按完整事件丢弃，保留控制记录与缺口顺序。磁盘满和硬 I/O 错误仍会停止采集。

## 回放与导出

- 支持 Linux SLL2 和混合链路类型的 PCAPNG 导入，按接口保留分段。遇到未知链路类型会报错，并指出无法读取的输入。
- 异常中断造成最后一条 PCAP 或 JSONL 记录残缺时，回放和导出保留此前完整的记录并报告缺口。原始证据保持只读。
- TLS 缺口按探针代次和在途连接归因，新建 HTTP/2 连接可以在缺口后继续还原。证据 ZIP 按两端 TCP 地址、端口、请求前后各 60 秒筛选报文，PCAP 原生事务还限定来源接口。同一窗口内重用相同端点仍可能产生重叠。
- 新增压测对账工具，按请求 ID 区分业务失败、原始采集缺失、离线回放缺失及正文截断。

## 下载与校验

共 10 个组件包。Ubuntu、CentOS 7+ 提供 amd64 和 arm64，Windows 提供 amd64。每个平台分别提供 `traffic` 采集器和 `traffic-console` 分析器，用同版本 `SHA256SUMS` 核对下载文件。完整解压并保留随包依赖。停采后，在分析机运行 `traffic-console analyze --session DIR`。

## 验证范围

- 在隔离 Linux ARM64、OpenSSL 3.0.13 环境验证了 eCapture 和 Preload 停采、采集器强制终止、eCapture 发送队列拥塞和连续四次探针重挂。过载实测启用了 `--evidence-backpressure=drop`。探针序号缺口统计的是事件。
- 采集对账压测仍观察到 libpcap 短突发时原始请求存在、离线事务缺失的情况。Windows IIS 多场景长压和物理 Linux 多发行版长压仍待验证。`tls_coverage=unverified` 表示实际覆盖率未知，排空确认只说明停采边界得到核对。
- 测试范围和细节见 [PR #11](https://github.com/Sunmedalia/traffic/pull/11)、[PR #13](https://github.com/Sunmedalia/traffic/pull/13) 和 [PR #14](https://github.com/Sunmedalia/traffic/pull/14)。
