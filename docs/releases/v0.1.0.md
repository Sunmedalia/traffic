# traffic v0.1.0

首个版本发布：面向网站应急响应的 HTTP/HTTPS 采集、中文终端与 Web 分析、可校验证据导出。

## 本次发布

- **采集完整性**：增加按后端、原因和单位记录的缺口事件，连接局部淘汰、截断后续消息恢复、目标进程启动身份及退出状态。
- **HTTP/2**：增加有界帧、HPACK、多路复用与 stream ID；中途附加缺少历史时保留原始证据并标记边界，完整实机矩阵待验收。
- **探针与存储**：Linux 内核目标范围过滤、原子预加载队列、紧凑事件和堆式重排；有界证据写入与 SQLite 批次。
- **终端分析**：全新四页框架、告警按规则/来源聚合、跟随与定格、命中高亮、查找、复制 ID、后台证据导出。合并 PR #4 后保留协议和采集诊断。
- **Web 与 JSON**：时间线、方法/状态/时间组合筛选、详情及证据导出；级别筛选统一为“不低于”。
- **环境诊断**：只读预检、资源预算、Linux cgroup v1/v2、显式网络命名空间与兼容性说明。

## 下载包

| 文件 | 内容与运行条件 |
| --- | --- |
| `traffic-v0.1.0-linux-amd64.tar.gz` | Linux x64 采集器、分析器、预加载库；Ubuntu 24.04 构建，glibc 2.39+ 与 libpcap |
| `traffic-v0.1.0-linux-arm64.tar.gz` | 同上，Linux ARM64 |
| `traffic-v0.1.0-windows-amd64.zip` | Windows x64 采集器、分析器、探针脚本；抓包需安装 Npcap，明文探针另需 Python/Frida 17.5.1 |
| `traffic-v0.1.0-java.zip` | Java Agent；JDK 17/21、支持的 Tomcat NIO 场景 |
| `SHA256SUMS` | 上述四个下载包的 SHA-256；包内另有逐文件清单与 BUILDINFO.json |

eCapture、Npcap、Frida 不包含在下载包中。Linux 包附带构建 eCapture 所需脚本及固定版本补丁，构建后保留能力清单与许可证。Java Agent 单独下载，解压后通过 `--java-agent` 指定路径。

CentOS 7 等旧 glibc 环境请从此 tag 的源码在目标系统构建，不能直接使用 Ubuntu 24.04 的预编译包。macOS 分析器可从源码构建。源码使用 GitHub 自动提供的 Source code 下载入口。

## 验证与已知限制

- 发布流程执行 Linux ARM64/x64 竞态测试、静态检查、构建及预加载原生回归，Windows 原生竞态测试/静态检查/构建，以及 Java Agent 验证。Windows 托管 runner 无 Npcap，两个依赖 libpcap DLL 的离线集成测试在 Linux 执行。
- 三台 Linux 预加载各完成 20 轮 × 19 请求复验，共 1,140 条；eCapture r38 功能回归核对 126 条。结果对应各自记录的构建，不是所有发布环境的运行保证。
- **持续高负载仍有 eCapture 接收预算耗尽与后端不可用样本**。正式低影响门槛、八小时长压、完整 Windows/容器/HTTP/2 矩阵和部分后端端到端排空尚未完成。
- 零观测丢弃不代表采全；启动窗口、已阻塞调用和退出尾部仍有未知边界。排空确认不等于运行时卸载。
- HTTP/3、WebSocket 内容、Go TLS、通用 JSSE 和 Tomcat NIO2 不在当前支持范围。

详细记录见此 tag 的 `VALIDATION.md`、`OPTIMIZATION.md` 与 `docs/guide.md`。

## 使用与升级

解压后先执行 `bin/traffic doctor`，使用 `--no-tls` 验证 HTTP 链路，再显式配置所需的 HTTPS 后端。预加载库须在服务启动时加载；现有环境请先阅读使用手册中的停止、回滚与清理。

采集命令使用 `traffic`；终端、Web、status/requests/events/show/export 使用独立 `traffic-tui`。旧会话继续可读；缺失的新诊断字段显示未知。`--severity medium` 现在匹配中危及高危。导出证据前仍需停止采集。
