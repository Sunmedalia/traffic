# traffic v0.1.2

- 分析器 `traffic-tui` 更名为 `traffic-console`，Web / TUI 与原有会话格式保持兼容。
- 采集器和分析器独立打包，共 10 个下载包：Windows x64，以及 Ubuntu / CentOS 7+ 的 x64、ARM64。
- Windows 采集包内置 WinDivert 签名驱动、便携 Python、Frida 和探针；无需另外安装 Npcap 或下载依赖包。`doctor` 不加载驱动；管理员运行 `capture` 时按需加载。
- Linux 主程序静态链接 libpcap，随包提供配套 eCapture、Java Agent、glibc 2.17 基线的 OpenSSL 预加载库。Ubuntu / CentOS 分别验证；CentOS 不再要求自行编译。
- 依赖自动按程序路径解析；Windows 探针默认配置，`--no-tls` 禁用明文附加。
- `traffic help`、`traffic <命令> --help` 与 `--cn-help` 提供命令专属帮助和使用示例；doctor 不再展示 capture 专属参数。
- 离线 PCAP / PCAPNG 导入不再依赖 Windows 抓包 DLL。

## 下载与升级

只采集下载 `traffic-v0.1.2-系统-架构`；分析下载 `traffic-console-v0.1.2-系统-架构`。请完整解压，不要单独复制 exe 或删除 deps。系统标识为 `ubuntu`、`centos7`、`windows`。Linux 使用 tar.gz，Windows 使用 zip。用 SHA256SUMS 校验。

```text
traffic --cn-help
traffic doctor --cn-help
traffic capture --cn-help
traffic-console --session 原会话目录
```

## 运行边界

Windows 采集仍需管理员权限及系统允许加载签名驱动。WinDivert 句柄没有队列丢弃计数，健康状态标记为未知；包时间采用接收时间。旧版 Windows Npcap 路径的既有验证不等于 WinDivert 完整性能验收。

CentOS 7 原生内核没有 CO-RE BTF，HTTPS 需在服务启动时加载随包预加载库；程序不会自动重启业务。Java attach 依赖目标 JVM 自身能力。已建立连接、TLS ABI、IIS 异步接收和高负载完整性等既有限制仍适用，详见 VALIDATION.md。
