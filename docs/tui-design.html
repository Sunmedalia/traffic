traffic-tui · 终端界面设计稿

应急响应分析终端：页面与使用逻辑

基于现有 cmd/traffic-tui 的会话选择、三标签页和详情视图重新规划。目标是让值守人员在一屏内回答三个问题：现在有没有人在打、打的是什么、采到的数据可不可信。

原则一 · 告警先于流量

进入会话先看到攻击态势，再按需下钻到单条请求，不让人从上万行请求里找告警。

原则二 · 一个键一个意思

同一按键在所有页面含义一致。Enter 永远是进入，Esc 永远是退一层，/ 永远是在当前位置查找。

原则三 · 可信度常驻

漏采、丢包、心跳过期直接影响结论，状态栏常驻显示，不藏在概览底部。

一、整体结构

界面分四层，逐层进入、逐层返回。带 新增 的是现有代码里没有的部分。

① 会话选择按主机分组列出采集会话，选一个打开
→
② 会话工作区1 概览　2 请求　3 告警　4 健康新增
→
③ 请求详情请求 / 响应 / 解码正文 / 检测依据
→
④ 弹层筛选、导出新增、帮助

现状对照：概览目前是一页纯文本，同时承担态势和采集诊断两件事；告警页只是加了条件的请求列表；TUI 里没有导出入口（只有命令行和 Web 有）。

二、通用框架

工作区每个页面都用同一套五行框架，只替换中间的内容区。

第 1 行 · 身份栏

主机 / 日期 / 会话名，采集状态，累计请求与告警数，刷新模式。任何页面都能看出自己在哪个会话、数据是否还在增长。

第 2 行 · 标签栏

告警标签带未读式计数。健康标签在有丢弃、探针异常或采集错误时显示黄色 !，失败时显示红色。

第 3 行 · 筛选条

当前生效的条件以标签形式列出，并显示命中条数。无筛选时显示「全部」。

倒数第 2 行 · 提示栏

优先显示刷新失败等错误，其次是采集可信度提醒。平时为空，不占注意力。

最后 1 行 · 按键栏

只列当前页面此刻可用的键，随页面和弹层变化。完整列表在 ?。

看什么

  • 按主机分组，组内从新到旧；正在采集的会话排在组内最前。
  • 改成对齐的列，每个会话一行；完整路径只显示选中那一行的。

能做什么

  • / 按会话名、主机名即时过滤新增。
  • o 输入会话目录、index.sqlite 或采集根目录。
  • 索引损坏的会话可见但打不开，提示栏给出原因。

进入规则

  • 带 --session 启动时跳过本页直接进工作区。
  • 工作区里按 s 回到本页，光标停在刚才的会话上。
  • 只扫到一个会话时仍停在本页，不自动打开，避免看错会话。

列表

  • 列对齐。状态码按 2xx 绿、4xx 黄、5xx 红着色；级别列同时有文字和颜色，高危整行标红。
  • 当天的记录只显示时分秒，跨天才显示日期。
  • 窄屏依次隐藏 Host、客户端端口，URL 永远保留并截断在行尾。

详情

  • 终端宽度 ≥ 120 列时左右分栏，否则详情全屏。
  • 有告警的请求默认打开「检测依据」标签，否则打开「请求」。标签上显示告警条数。
  • 匹配片段在依据和原文中都反色高亮新增；/ 文内查找，n/N 跳转新增。

从一条请求出发

  • c 只看这个客户端，m 只看这条规则，H 只看这个 Host新增。
  • J/K 不退出详情直接看上下一条新增。
  • e 导出证据，y 复制请求 ID新增。

三种视图，v 循环

  • 按规则（默认）：一条规则一行，先知道是什么攻击。
  • 按来源：一个客户端 IP 一行，显示命中数、涉及规则数、首次与最近时间。
  • 逐条：就是现有的告警列表，与请求页同一套列和详情。

下钻

  • 在聚合行上按 Enter：把该规则或来源加入筛选条，切到「逐条」视图。
  • Esc 回到聚合视图并去掉刚加的那个条件，光标回到原行。
  • 聚合视图同样受筛选条约束，例如先限定时间窗再看规则分布。

为什么单独一页

这些信息回答的是「数据可不可信」，和「有没有攻击」是两件事。分开后概览能专注态势，这里可以放全量诊断而不必压缩。

何时提醒

  • 任一丢弃计数 > 0、探针未附加、推送失败或有采集错误：标签栏 「4 健康」 变黄。
  • 状态为采集失败或心跳过期：变红，并在提示栏常驻。
  • 完整性提示作为页首横幅，始终显示。

筛选

  • 级别和服务改为选项，不再手打 low/medium/high。级别按「不低于」理解。
  • 时间接受 30m、2h、today、14:30、11-16 14:30 和 RFC3339，输入时下方实时换算成绝对时间。
  • 新增「时间到」，可以框定一个时间窗新增。
  • 服务选项取自本会话实际出现过的服务。

导出

  • 在详情或列表选中行上按 e。默认文件名带请求 ID，目标已存在时报错，不覆盖。
  • 完成后提示栏显示绝对路径和压缩包大小；失败时弹层保留并显示原因。
  • 复用现有 exportEvidence，在后台执行，界面不冻结。

刷新：跟随、定格、暂停

现在的问题是光标停在第一页时，新请求不断把行往下推，正在看的那行会移走。改为三种明确的状态，身份栏右侧始终显示当前是哪一种。

状态何时进入行为如何离开
跟随中光标在第 1 页第 1 行新记录从顶部进入，光标始终在最新一条移动光标、翻页或打开详情
已定格光标离开顶部，或详情打开列表锚定在当前首行，行不再移动；页脚显示「↑ 新增 N 条」；计数继续更新g 回到最新并恢复跟随
已暂停按 空格完全停止查询，计数也冻结再按 空格，回到暂停前的状态
静态会话已完成、已停止或是导入的 PCAP不显示刷新状态，只低频检查状态文件—

定格用的是现有翻页锚点机制（按首行的时间和 ID 定位），把它从「第 2 页起生效」扩展到第 1 页即可。

筛选

作用范围

  • 一个会话一套筛选，请求页和告警页共用，条件之间是「并且」。
  • 概览和健康页不受筛选影响。
  • 切换会话时恢复为启动参数给出的初始条件。

四个入口

  • / 打开表单，一次改多个条件。
  • c m H 从选中行直接取值。
  • 概览区块上的 Enter。
  • 告警聚合行上的 Enter。

反馈

  • 每个条件在筛选条上是一个标签，带命中条数。
  • 结果为空时内容区写明「当前筛选无匹配，按 x 清空」。
  • 应用筛选后回到第 1 页并恢复跟随。

五、三条典型路径

实时值守

  1. 打开正在采集的会话，停在概览。
  2. 告警计数跳动，看「最近高危」。
  3. Enter 打开详情，看匹配片段和响应状态码判断是否打成功。
  4. c 只看这个来源，确认它还做了什么。
  5. e 导出，1 回概览继续盯。

事后回溯

  1. 会话选择页按 / 找到事发那天的会话。
  2. 4 先看健康，确认那段时间没有大量丢弃。
  3. 3 告警页按规则看全貌，v 换成按来源。
  4. Enter 下钻到最可疑的来源。
  5. x 清筛选后用 c 看它的全部请求，包括没触发规则的。

按线索查

  1. 已知攻击者 IP 或一个 URL 片段。
  2. 2 请求页，/ 填客户端或关键词，时间从填 2h。
  3. J/K 在详情里连续翻看。
  4. 详情内 / 查找响应里的敏感字段。
  5. 逐条 e 导出需要留存的请求。

需要你定的三件事

  • 进入会话后默认停在哪页。建议概览；如果你们主要用于盯实时流量，可以改成请求页。
  • 级别筛选的含义。设计里改成「不低于」，命令行 --severity 目前是精确匹配。建议两边一起改，否则同一个词两种含义。
  • 关键词是否搜正文。现在只搜 Host 和 URL。搜请求和响应正文对排查很有用，但在几万条记录的会话上会慢，设计稿里暂未包含。
