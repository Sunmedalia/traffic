# IIS 附加后请求遗漏修复与验收

本次修复针对 Windows 10 LTSC 17763 / IIS 10 实机上，动态附加后前十条 HTTPS 请求消失，以及快速长连接中的额外请求、正文或结束标记缺失。发布包尚未更新；使用当前源码构建的采集器和配套探针。

## 实现

- 在已完成的 I/O 上下文以及正文读取/响应发送 API 中，有界、只读地发现 `HTTP_REQUEST` 指针。按本次 API 请求 ID、公有结构字段、协议、方法、URL、地址、TLS 和所选端口交叉校验；不重新投递接收，不读取业务流，不改请求或响应。
- 已登记接收与恢复接收共用请求 ID 去重，避免晚到完成通知重复写入正文和请求。恢复计数通过 `probe_recovered_receives` 单独报告。
- HTTP API 的同步返回使用 Frida 自身的 `onLeave`，不再依靠手工返回帧配对，从而覆盖嵌套、并发的正文读取和响应结束。异步完成仍用已登记的 OVERLAPPED；无关完成和不可读指针不使 helper 退出。
- 取消“必须预热十余条”的提示。常规验收默认零预热，新增 `scripts/windows/verify-iis-startup.py`，按客户端逐条账本检查前十条、全部请求、正文、配对及进程/配置身份，缺失或不完整则非零退出。
- 新增 Node VM 回归，执行实际探针脚本，覆盖不同指针位置、无关/无效完成、请求 ID 约束、响应先到、去重、正文和发送函数返回回调。加入 CI；状态字段和错误报告也有 Go 回归。

这里的完成上下文是有界启发式识别，不是 Windows 对第三方上下文布局的兼容承诺。其它 IIS/Windows 版本、不同处理链和未覆盖路径需要各自验收，不能推广为任意 IIS 零漏采。

## 保留的失败与业务影响

早期候选通过了简单请求，但混合正文和并发复验发现遗漏或不完整，均未计为最终验收通过。尝试在附加时登记已阻塞线程及更改返回点拦截方式的候选，实机出现一次 `w3wp.exe` 在 `frida-agent.dll` 中的 `0xc0000409` 崩溃（Windows 事件时间 22:51:47，PID 1332）。该候选已撤除，最终方案不再枚举线程寄存器或安装这些附加返回回调。

测试站随后由正常请求启动新的工作进程。最终验收必须以新工作进程的身份为基线，不能再声称本轮全部工作期间 IIS 进程始终未变。崩溃事件、各失败候选会话及原始证据均保留在隔离目录。

## 证据与边界

远端 `C:\traffic-iis-fix-20261117`；本地 Git 忽略目录 `validation/windows-iis-fix-20261117/`。`final-acceptance.json` 是最终汇总，`accepted-artifacts.zip` 包含逐轮客户端账本、原始事件、PCAP、分析结果、状态、日志及导出 ZIP，`accepted-receipt.json` 记录本地复核及归档哈希。历史失败未计入上述通过统计。

目标机可继续使用 `C:\traffic-iis-fix-20261117\bin\traffic.exe`，配套探针位于其 `scripts\`，Python/Frida 位于其 `deps\python\`。这是隔离测试构建，尚未发布；采集时仍需显式指定该探针和 Python 路径。旧安装中的探针不会自动更新。

即使样本全部通过，`tls_coverage` 仍为 `unverified`。已完成并离开进程的请求不能补回；内核缓存、其它 ABI、HTTP/2、TLS 1.3、持续高负载和长压不属于本轮证明范围。停止时应分别检查数据排空、hook 恢复、脚本卸载及传输脱离；Frida 运行时可能仍驻留。

20 轮的数据排空全部确认，19 轮确认 hook 字节恢复；重复附加第 3 轮 `hooks_removed=false`，因此 hook 清理的全轮验收未通过。最终常规矩阵报告 `hooks_removed=true`，但所有轮次 `script_unloaded=false`、`transport_detached=false`，不能声称完整运行时卸载。请求完整性通过与生命周期缺口分别报告，本次没有通过回收应用池清理运行时。
